## JWT & Token Management (Best Practices)

Timezone Consistency: Always use DateTime.UtcNow for JWT generation and expiration. Using local time (DateTime.Now) causes critical authentication bugs across different server timezones and during Daylight Saving Time (DST) changes.

JWT Claims Standards: Use standard claim types. Use sub (Subject) for user IDs and ClaimTypes.Name for usernames to maintain correct claim semantics.

Performance Optimization: Use a single or static instance of JwtSecurityTokenHandler because it is thread-safe. Avoid instantiating it per request to save CPU cycles.

## Token Security & Hashing
The Golden Rule of Refresh Tokens: Never persist the plain-text refresh token in the database. If the database leaks, sessions are hijacked.

The Flow: Send the plain-text token to the client via an HttpOnly cookie, but store the SHA-256 hash of that token in the database. During a refresh request, hash the incoming plain cookie value and perform a database lookup against the hashed column.

SHA-256 vs. Bcrypt: Use SHA-256 for refresh tokens because they are already high-entropy random bytes (e.g., 64 bytes) generated by a secure crypto provider. Slow hashing algorithms like Bcrypt or Argon2 are designed to protect low-entropy, human-made passwords, not random cryptographic strings.

## ASP.NET Core Configuration Architecture
Options Pattern: Avoid using "magic strings" like _config["JWT:SigningKey"] scattered across services. Instead, bind strongly-typed configuration classes (JwtSettings) in Program.cs.


Implementation: * Register it: builder.Services.Configure<JwtSettings>(builder.Configuration.GetSection("JWT"));
Inject it: Use IOptions<JwtSettings> inside your services.

Benefits: Provides a single source of truth, enables IDE IntelliSense, prevents typos, and makes unit testing significantly easier because you can effortlessly mock IOptions<T>.

## API Design & Code Quality
Fail-Fast Principle: Check for null or empty cookies at the very beginning of a refresh request. This prevents unnecessary database queries, protecting your application from database exhaustion attacks.

C# Naming Conventions: Asynchronous methods must always use the Async suffix (e.g., CreateTokenAsync), ensuring readability and clear intent for developers using the API.

Data Separation: Use distinct models for distinct destinations. For example, a wrapper class like RefreshTokenResult helps cleanly split data intended only for the browser cookie (plain text) from data intended only for the database (the hashed entity).
## Security Hardening (Next-Level Interview Answers)
When asked how to further secure this setup, mention these intermediate-to-advanced steps:

Secrets Management: Move the JWT SigningKey out of appsettings.json and store it in Environment Variables or AWS Secrets Manager/Azure Key Vault.

Cookie Security: Ensure the refresh token cookie uses HttpOnly = true (prevents XSS), Secure = true (forces HTTPS), and SameSite = SameSiteMode.Strict (mitigates CSRF).

Database Hygiene: Implement a background worker or an on-login routine to prune/delete expired or revoked refresh tokens so the database table doesn't grow indefinitely.
